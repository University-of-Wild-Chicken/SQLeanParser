# Unchanged DISTINCT FROM sources

This fixed population contains 50 unchanged complete SELECT statements:
18 PostgreSQL regression inputs, 20 Materialize regression inputs, and 12
DuckDB regression inputs. There are 59 null-safe comparisons: 37
`IS DISTINCT FROM` and 22 `IS NOT DISTINCT FROM`. They include literal NULLs,
integer-width comparisons, multiple projections, Boolean precedence, filters,
and joins. These are actual upstream test inputs, not production traffic or
queries generated by this project.

`concrete_sources.json` records complete statement/query-block selectors,
commit pins, file and SQL SHA256 hashes, source links, licenses, and the closed
source counts:

- [PostgreSQL](https://github.com/postgres/postgres/tree/f0595c3d839debdb140903621c1b44a4f4d86256):
  PostgreSQL license; existing pinned SQL snapshots and license are reused.
- [Materialize](https://github.com/MaterializeInc/materialize/tree/726570dba1d2e4d839c707a84a986fb3b3acc5c3):
  Business Source License 1.1, change date 2030-10-20, change license Apache-2.0.
  This is source-available code; its retained license is not replaced by this
  project's license.
- [DuckDB](https://github.com/duckdb/duckdb/tree/917243df252f114d9c448b1d23f8618f0d683769):
  MIT. Complete selected SQLLogicTest input blocks are retained, including
  their source newlines. Expected output sections are opaque.

The finite source observer records operator spelling, UTF-8 byte location,
immediate left/right raw-AST forms, and a structural `source_free` flag. It
does not infer table types or compare upstream expected results. SQL, casts,
aliases, and parameter markers are not rewritten. Source SQL and test
programs are never executed.

Exactly 25 independently selected closed statements receive full static
certificates with 34 ordered BOOL output positions, all nonnullable. The
eight PostgreSQL labels are `yes`, `no`, `yes`, `no`, `no`, `yes`, `no`, `yes`;
the remaining positions use `?column?`. The ten-projection DuckDB query is
one source statement, not ten examples. The fixed registry is stored in
`../null_predicates/source_contracts.json` and checked against a separately
declared Lean registry. The other 25 queries depend on upstream relations and
receive identity/PostgreSQL checked rendering without an invented catalog.

The Materialize finite prefix reader has an explicit factor opt-in for the
selected Boolean query headers; the stricter default reader is unchanged.
It recognizes complete preceding records without interpreting their results.
Unknown control directives fail extraction.

```sh
python3 scripts/extract_factor_corpus.py --factor distinct_from --check
python3 -m unittest discover -s scripts -p 'test_null_predicate_extraction.py'
```

The optional `--oracle` mode recomputes syntax observations with pinned pglast
7.21. Reproduction otherwise uses only the standard library, retained source
files, selectors, and hashes. Native value tests use separately authored
queries and explicitly separate PostgreSQL and SQLite expectations.
