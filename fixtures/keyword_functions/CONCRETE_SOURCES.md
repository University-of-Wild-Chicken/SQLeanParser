# Unchanged keyword-function source corpus

This fixed population contains 50 complete, unchanged SELECT statements using
unquoted `left(...)` or `right(...)`: 34 DoltgreSQL generated engine regression
cases, 14 Materialize engine regression cases, one PostgreSQL regression
statement, and the shipping River `indexReindexArtifacts` query. There are
51 calls in total: 26 `left` and 25 `right`; the PostgreSQL statement projects
both calls. The selected sources cover empty and nonempty strings, Unicode
combining characters, NULL arguments, positive and negative lengths, and the
two INTEGER boundaries.

Sources, complete-statement/token selectors, commit pins, source links, licenses,
and SHA256 hashes are recorded in `concrete_sources.json`:

- [PostgreSQL](https://github.com/postgres/postgres/tree/f0595c3d839debdb140903621c1b44a4f4d86256),
  PostgreSQL license; the existing `text.sql` snapshot is reused.
- [River](https://github.com/riverqueue/river/tree/1354a059d7cbe5790acc7a755a2ab7ac6d2f1ed8),
  MPL-2.0; the existing generated SQLC constant is decoded without SQL rewrites.
- [Materialize](https://github.com/MaterializeInc/materialize/tree/726570dba1d2e4d839c707a84a986fb3b3acc5c3),
  Business Source License 1.1, change date 2030-10-20, change license Apache-2.0.
  Its existing license and `test/sqllogictest/string.slt` snapshot are reused.
- [DoltgreSQL](https://github.com/dolthub/doltgresql/tree/b905594b000601fc5ea8db38c432b21683af01fb),
  Apache-2.0. Two complete pinned files,
  `testing/generation/function_coverage/output/left_test.go` and `right_test.go`,
  and the license are retained. These are checked-in generated regression
  statements, not production traffic and not queries generated by this project.

For DoltgreSQL, the finite Go reader selects a complete plain quoted string in
the exact `{ Query: "...",` field context. The selector binds the token index
and both source offsets. The opt-in is restricted to this source/factor pair;
the original map/call reader behavior is unchanged. Escaped or raw strings,
concatenation, descriptions, expected-result fields, comments, and incomplete
quoted regions do not supply selected SQL. The Go files and test directives
are never executed. Materialize SQLLogicTest result sections are opaque and
the existing prefix reader is unchanged.

`observed_syntax.keyword_functions` records function name, UTF-8 byte location,
immediate argument node forms, immediate literal NULL flags, and directly
written `int4` casts. It preserves the distinction between a direct cast and
unary minus applied to a cast. It does not infer types for column or function
operands. The `source_free` flag is a structural observation and is not itself
a validity certificate.

The independently fixed full-certificate population contains 49 closed
statements with 50 ordered TEXT output positions; four positions are nullable.
They use only literal inputs and explicit INTEGER casts. The River query uses
actual PostgreSQL catalog relations, a CTE, and two unspecified input bindings,
so it receives checked rendering only. Its unique parameter-slot inventory is
`[1, 2]`; its lexical occurrence sequence is `[1, 2, 1, 1]`. No application
catalog, parameter types, or runtime values are invented for it.

Source SQL is never executed, and upstream expected results are not native
PostgreSQL oracles. In particular, `right(text, -2147483648)` has differing
observed behavior between the local PostgreSQL 16.15 installation and the
pinned PostgreSQL source revision. The unchanged source examples establish
syntax, exact output typing, and serialization evidence; native value checks
use separately authored cases with an explicit engine version.

The broader PostgreSQL `TYPE_FUNC_NAME_KEYWORD` category is a parser concern.
This source factor covers `LEFT` and `RIGHT`; it does not imply native function
signatures for arbitrary keyword-spelled names. Source discovery found
`current_schema()` in this category already covered by the earlier context
factor. DuckDB's `{FUN}` substitution templates and a RisingWave file containing
an unsupported setup directive were excluded rather than rewritten.

```sh
python3 scripts/extract_factor_corpus.py --factor keyword_functions --check
python3 -m unittest discover -s scripts -p 'test_keyword_functions_extraction.py'
```

recompute the original PostgreSQL syntax observations. Offline reproduction
requires neither network access nor source execution.
