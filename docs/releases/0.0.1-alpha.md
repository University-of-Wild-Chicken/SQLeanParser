# SQLean 0.0.1-alpha — planned release

**Not released.** Publication is explicitly held until full typed-validity and
renderer contracts cover PostgreSQL. The inventory below describes the current
development state, not a completed release or a waived requirement.

The current work adds the complete pinned PostgreSQL 16.15 context-free grammar as
a separate proof-carrying syntax interface, and expands the typed SELECT
interface through scalar functions, conditional expressions, row locking and
independent JOIN and nested non-LATERAL derived-source validity, array types,
ARRAY constructors, quantified array comparisons, array subscripts/slices,
direct row-constructor comparisons, scalar and array concatenation, ILIKE/regex
matching, JSON/JSONB extraction, JSONB containment, array containment/overlap,
temporal EXTRACT, interval field/range qualifiers, SQL-standard SUBSTRING,
schema-qualified relation names with explicit namespace metadata, and JSONB
existence operators with role-sensitive template bindings, context values
with exact NAME types, named/default function arguments, and keyword function
heads with exact LEFT/RIGHT signatures.
It retains the earlier SQLite/PostgreSQL, CRUD, join, grouping, subquery,
recursive CTE, parameter and table-DDL interfaces.

## Assurance levels

- **Grammar derivation and original-source rendering:** all 3,284 upstream
  source productions are imported from PostgreSQL commit
  `f0595c3d839debdb140903621c1b44a4f4d86256`. Successful recognition carries an
  independent Lean grammar derivation over the complete token stream. Original
  source reconstruction is exact. The lexer, precedence choices and PostgreSQL
  C semantic actions are not universally proved equivalent to PostgreSQL.
- **Independent SELECT validity:** `sqlean-basic-select-v0.27` certifies the
  supported source-free/base-table/derived-source JOIN fragment, including concrete scalar
  types, ordered parameter uses, scalar signatures, CASE and related forms,
  pagination, CROSS/INNER/LEFT/RIGHT/FULL JOIN with ON/USING/NATURAL matching,
  merged and qualified columns, positional derived column aliases, global
  parameter order through nested queries, supported row-lock targets, and
  array types/casts/bindings with exact element identities, and ARRAY
  constructors with contextual element casts, and ANY/SOME/ALL array comparisons
  with exact scalar operator signatures, and grouped array subscripts/slices
  with assignment-converted bounds and exact element modifiers. Direct row
  comparisons retain pairwise scalar operators and admitted B-tree strategies.
  Scalar concatenation retains its exact text/polymorphic/JSONB/BYTEA family.
  ILIKE and regex retain TEXT/TEXT or bpchar/TEXT selection and NULL propagation.
  JSON field/element/path extraction retains all twelve concrete operator
  declarations and nullable JSON/JSONB/TEXT results. JSONB containment retains
  its two native declarations, unknown-input disambiguation and NULL propagation.
  Array concatenation, append and prepend retain their common-element types
  and distinct non-strict NULL rules.
  Array containment and overlap instead require equal element identities,
  admitted element equality and strict outer-NULL propagation.
  EXTRACT retains six temporal signatures, NUMERIC results and conservative
  nullable metadata for infinite DATE and TIMESTAMP values.
  Interval qualifiers retain all thirteen exact field masks and optional
  precision through scalar/array casts, catalog columns and compatible
  conditional expressions. Excess precision remains an explicit coverage gap.
  SUBSTRING retains its six admitted TEXT/BYTEA declarations, FOR-only's
  explicit INTEGER conversion and lexical parameter order for reversed
  FOR/FROM syntax. Regex overloads conservatively retain nullable results
  because a nonmatching pattern can return NULL.
  Schema-qualified names retain separate components, exact relation identity,
  and caller-declared unqualified visibility. Ordered relation namespaces
  preserve alias hiding, ambiguity before column lookup and the first matching
  row-lock OF target. Database qualification, `pg_temp` alias resolution and
  whole-row function notation remain explicit gaps.
  JSONB existence retains three strict declarations, string/array key coercion,
  outer-NULL propagation and the competing geometric `?|` overload when both
  operands are unknown. Only primary question marks consume binding slots.
  Seven context-value forms and six session functions retain their native NAME
  or TEXT result and conservative nullable flags. NAME remains distinct from
  TEXT across directional casts, operators, arrays and common-type selection.
  Context values retain their native labels, independently of catalog
  namespace metadata.
  Named calls retain `=>`/`:=` spelling and lexical expression order.
  Independent slot binding checks a positional prefix, exact declared names,
  uniqueness and omitted defaults. The fixed `make_interval` declaration
  supplies six INTEGER slots, one FLOAT8 slot and seven typed zero defaults.
  Other named routines remain explicit typed-contract gaps.
  LEFT/RIGHT use exact TEXT/INTEGER declarations, implicit string/SMALLINT
  coercions and strict NULL propagation. Generic keyword function heads do
  not acquire typed declarations merely by parsing successfully.
  Inferred
  cast, CASE and subscript labels follow the covered PostgreSQL naming rules.
  Parameter modifiers
  normalize to PostgreSQL's analyzed OID types; explicit casts retain modifiers.
  The broader query and statement families
  retain the expanded executable-check tier.
- **Checked typed-AST rendering:** identity and PostgreSQL profiles establish
  exact parser roundtrip and parameter transport for admitted SELECT ASTs.
  General translation/idempotence/serialization proofs cover the new
  constructors. SQLite has a separately checked, smaller rendering domain.
- **Native observations:** finite SQLite and PostgreSQL tests compare bound
  source/canonical queries. These observations do not prove universal
  execution equivalence, transaction isolation, successful conversion of
  arbitrary literal values, or freedom from runtime errors.

The source and compiled declaration audits reject proof placeholders, custom
axioms, unsafe proof shortcuts and native decision shortcuts. Lean's standard
foundational axioms (`propext`, `Classical.choice`, `Quot.sound`) remain in the
trusted foundation; this is not a claim of an axiom-free foundational system.

## Remaining work

The full PostgreSQL grammar has **not** been translated into the typed SQL
AST with independent full-query validity, checked rendering and parameter
preservation contracts. Independent SELECT validity still excludes LATERAL,
grouping, aggregate queries, CTEs and expression subqueries; mutations, DDL and utility statements do not gain
that guarantee from grammar acceptance. Grammar completeness and lexer/action
equivalence also remain open.

The requested 50 unchanged concrete examples per entire-grammar factor are
not complete. Available examples, distinct populations and shortages are
recorded explicitly without synthetic replacements.

Build with Lean 4.34.0 using `lake build`. The CI workflow rebuilds the proofs,
audits trust dependencies, regenerates fixtures and grammar tables, and runs
the Lean, Python, SQLite and PostgreSQL 16 suites. See the
[project README](../../README.md) and the
[grammar interface documentation](../../fixtures/postgresql_grammar/README.md)
for commands and certificate boundaries.
